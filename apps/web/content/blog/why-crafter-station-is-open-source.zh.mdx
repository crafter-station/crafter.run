Crafter Station 最初只是秘鲁一群想动手做东西的人建的 WhatsApp 群。如今我们在拉美有一千多位 builder，在 [github.com/crafter-station](https://github.com/crafter-station) 上有 219 个公开仓库。我们做的几乎所有东西都可以阅读、安装和 fork。

我们从来没有开会决定要开源。公开构建从第一个仓库起就带来了回报，所以我们一直这样做。这篇文章讲讲原因。

## 公开的代码就是你的简历

当你有一个大家在用的仓库时，没人会问你读的是哪所大学。学位说明你通过了课程，而一个有 issue、pull request 和真实用户的仓库说明你能把东西做出来并发布。

对秘鲁的 builder 来说，这一点分量很重。远程招聘的公司、研究项目和基金都不会当面认识你，但他们可以读你的 GitHub。

## 开放的作品会走得比你计划的更远

[petdex](https://github.com/crafter-station/petdex) 是一个为 Codex、Claude Code 等编程智能体准备的动画宠物图库，已经有超过 4,300 颗星。[elements](https://github.com/crafter-station/elements) 是我们为 shadcn/ui 做的全栈组件块，超过 550 颗星。[text0](https://github.com/crafter-station/text0) 超过 450 颗星。

它们背后都没有任何推广活动。有人发现了它，装上了，再分享给别人。封闭的项目要靠你去推销，开放的项目只要足够好，自己就能找到路。

## 智能体只会推荐它读得到的东西

越来越多的人通过问模型来发现工具，而模型只能推荐它读得到的东西。所以这个网站有 `llms.txt`，每篇文章都有 markdown 版本，我们写 README 时也会让智能体能看懂每个仓库是做什么的、怎么用。

对智能体来说，封闭的代码并不存在。

## 公开地做，学得更快

仓库公开后，任何人都可以开一个 issue 告诉你哪里有问题。一开始会有点不舒服，但这也是进步最快的方式：一个陌生人的 issue，往往比同一团队再审一次教会你更多。

把工作写下来并公开发布，也逼着我们真正理解它。如果我们没法在 README 里讲清楚，那就说明还没做完。

## 开源不意味着什么

开源不意味着什么都不收费，也不意味着没有产品。Crafter 的一些项目会有付费版本，这没问题。开源意味着工作是可见的：代码、决策，还有犯过的错。

## 如何加入

- 浏览 [github.com/crafter-station](https://github.com/crafter-station) 上的仓库，挑一个你已经在用的。
- 提一个 issue 或 pull request。贡献者会按仓库获得权限。
- 加入我们的 [Discord](https://discord.gg/NRDWrGnxTU) 社区，告诉我们你在做什么。

无论你是在秘鲁还是拉美任何地方构建，这里都欢迎你。
